# Описания файлов кода

## Зачем

Описание файла — короткий ответ на вопрос «что делает этот файл и зачем он
нужен». Его находит семантический поиск (`rootgraph_semantic_search`, результат
с `kind: file_description`), и оно попадает в раздел «Описание файлов»
`assembled_docs.md`. Если у файла есть шапка-комментарий (package doc,
docstring модуля, заголовочный блок), Rootgraph берёт её сам как описание с
источником `comment` — такие файлы в списке не появляются. Пишем описания
только для файлов без шапки (`missing`) и для тех, чьё описание, написанное
агентом, устарело после правки файла (`stale`).

## Когда начинать

Порядок работ: сначала индексация и граф, потом описания файлов, потом подписи
секретов, потом обогащение документов. Не начинай описания, пока индексация не
завершилась. Если `rootgraph_files_undescribed` ответил `not_ready: true`
(`reason: indexing_in_progress`), файлов ещё нет в списке: раз в 30–60 секунд
вызывай `rootgraph_status` и жди `index_run.status = done`, затем повтори вызов.
Подписи секретов и обогащение документов идут только после описаний файлов.

## Протокол

**Стоп-правило.** Если любой вызов `rootgraph_*` (в том числе внутри субагента) вернул ошибку «проект заблокирован» — немедленно остановись, ничего не повторяй, не запускай новых субагентов и сообщи пользователю текст ошибки.

1. Вызови `rootgraph_files_undescribed` (по умолчанию 30 файлов). Ответ
   содержит `total_files`, `missing`, `stale`, `files[]`, `next_after`,
   `project_language` (`en` или `ru`) и `instruction`.
2. Если файлов до 5 — опиши их сам: прочитай каждый (Read) и ОДИН раз вызови
   `rootgraph_file_describe_save` с `items=[{file_path, description}, ...]`.
3. Если больше 5 — раздели список на пачки по 10 путей и для КАЖДОЙ пачки
   запусти отдельного субагента инструментом Task (`general-purpose`). Все
   вызовы Task делай ОДНИМ сообщением, чтобы пачки шли параллельно. Субагент
   читает файлы своей пачки и один раз вызывает `rootgraph_file_describe_save`;
   в ответ возвращает только «сохранено N».
4. После возврата всех субагентов снова вызови `rootgraph_files_undescribed`.
   Не больше 3 раундов подряд; если после них `missing + stale` больше нуля —
   одной строкой скажи пользователю, сколько файлов осталось, и предложи
   `/rootgraph-describe`. Файл, вернувшийся в списке сразу после сохранения,
   пропусти.

Инструкция в самом ответе `rootgraph_files_undescribed` — источник истины по
формулировке промпта субагента; выполняй её дословно.

## Стиль описания

- 1–2 предложения (15–600 символов, лучше около 150): что файл делает и зачем
  нужен в проекте.
- Без пересказа кода, без имён переменных и ссылок на номера строк, без вводных
  «Этот файл...».
- Язык описания — язык проекта: поле `project_language` (`en` или `ru`) в ответе
  `rootgraph_files_undescribed`, он задаётся при создании проекта. Имена файлов
  и символов оставляй как в коде.
- Никаких секретов, токенов, паролей и внутренних адресов: описание уходит на
  сервер, клиент блокирует находки сканера секретов.
- Если у файла есть `previous_description` и он всё ещё верен — перефразируй
  его, не выдумывай заново.

## Когда спрашивать пользователя

Если `missing + stale` больше 30 — не запускай субагентов молча: скажи число и
оценку стоимости (примерно N/10 субагентов) и спроси. Для 30 и меньше делай без
вопросов, но после срочной задачи пользователя, а не вместо неё.

## После собственной работы

Если ты только что создал или сильно изменил не больше 5 файлов кода, в конце
задачи вызови `rootgraph_files_undescribed(limit=10)` и опиши их сам, без
субагентов. Изменённый файл с описанием от агента снова станет `stale` после
индексации — это нормально.

## Чего не делать

- Не перезаписывай `manual`-описания: их пишет пользователь, они не возвращаются
  в список; `source: "manual"` в `rootgraph_file_describe_save` — только когда
  пользователь сам продиктовал текст.
- Не правь сами файлы кода ради описаний.
- Не вызывай `rootgraph_index` ради описаний: индексация сама отправляет шапки
  файлов и хэши, а список «без описания» приходит с сервера.
- Если сервер вернул ошибку «не поддерживает описания файлов» — не повторяй
  попытки, скажи пользователю обновить сервер.
