# /rootgraph-describe

Дописывает описания «что делает файл» для файлов кода, у которых их нет
(`missing`) или описание устарело после правки файла (`stale`). Описание
ищется семантическим поиском (`kind: file_description`) и попадает в
`assembled_docs.md`. Подробный протокол и стиль текста — навык
`rootgraph-file-descriptions`.

Сначала вызови `rootgraph_status`. Если `configured: false` — скажи
пользователю, что нужен `rootgraph_init`, и остановись, ничего дальше не
делай.

Аргументы команды: `$ARGUMENTS`. Разбор:

- пусто — `limit = 30`, без префикса;
- число — `limit = это число` (не больше 100);
- `all` — описать всё: до 3 раундов по 100 файлов. Перед стартом назови
  пользователю, сколько файлов осталось (`missing + stale` из первого ответа)
  и примерное число субагентов (файлов / 10), и продолжай ТОЛЬКО после его
  явного «да» в чате;
- любое другое значение — путь-префикс (`prefix`), `limit = 30`.

## Шаги

1. Вызови `rootgraph_files_undescribed(limit, prefix)`.
2. Если `files` пуст — скажи «Все файлы кода описаны.» и закончи.
3. Иначе выполни `instruction` из ответа дословно (для больше 5 файлов —
   субагенты через Task пачками по 10, все вызовы одним сообщением; для
   5 и меньше — опиши сам).
4. Когда всё сохранено, выведи ровно одну строку итога:
   `Описано: N, осталось: M` (M = `missing + stale` из последнего ответа
   `rootgraph_files_undescribed` или `rootgraph_file_describe_save`).

## Чего не делать

- Не правь сами файлы кода — команда только пишет описания через
  `rootgraph_file_describe_save`.
- Не описывай файлы вне списка, который вернул инструмент.
- Если `saved` меньше ожидаемого — повтори проблемные файлы не больше
  одного раза, дальше просто назови число оставшихся.
- Не вызывай `rootgraph_index` ради описаний.
